# Design Decisions

Each entry: date, decision, rationale.

## 2026-09-28 — Project setup (from clarification)
- **Stack:** Python engine (`engine/pa_bench`) for generation, retrieval, pipelines, benchmark, and metrics, plus a Next.js UI (`web/`) deployed on Vercel. The Python engine is also exposed through Vercel Python functions (`api/`) for about 10 curated live Workbench cases.
- **Benchmark execution:** full runs and threshold sweeps happen locally from the CLI. The Vercel app shows precomputed results and never computes the reported benchmark numbers itself.
- **Clinical notes:** Claude Code (Anthropic, a different model family from the GPT baseline) writes them once, in session, from seeded per-note fact plans. They're frozen as JSON in `data/notes/` and never regenerated at benchmark time. This reduces the risk of the GPT baseline being judged on text in its own style. Caveat: the note text was written by an LLM, not generated by code, so reproducibility comes from the frozen files, not from re-running a script.
- **Index date:** every PA request is dated **2026-09-01** (`PA_INDEX_DATE`). The clinical history spans about 12–24 months before it.
- **Policies:** normalized from public payer sources that I research. Every criterion is flagged `human_verification_required: true` until the user confirms it.
- **Evidence annotations:** stance labels are written against *concept-level* criterion IDs (`bmi`, `comorbidity`, `weight_management_program`, `program_duration`, `diet`, `exercise`, `inadequate_response`, `concurrent_glp1`) in Phase 1, then mapped onto payer-specific criteria in Phase 2. This keeps the dataset independent of the policy choice.
- **Data separation:** `data/cohort/` (canonical truth), `data/_generation/` (plans), and `ground_truth/` are generator- and evaluation-only. Only `data/fhir/` and `data/notes/` are model-visible. `engine/pa_bench/guard.py` will enforce this in code.

## 2026-09-28 — Cohort spec clarifications (M1.1)
- **GLP1-041:** the structured BMI series has an earlier reading of **30.3** (the spec's `current_bmi`) and a most recent reading of **29.8**, per scenario `latest_bmi_29_8`. The latest weight is derived for 29.8 at 175 cm (about 91.3 kg).
- **GLP1-029:** the BMI Observation records **30.0**, as EHRs usually store one decimal, with weight 79.7 kg and height 163 cm (a recompute gives 29.997). The policy evaluator uses the *recorded* BMI Observation value, and this rule applies cohort-wide.
- **GLP1-030:** the BMI Observation records the spec value **29.95**.
- **GLP1-040/041:** these BMI-conflict scenarios are stored in the spec's `medication_scenario` field. They're realized as data conflicts, and these patients have no anti-obesity medication history.

## 2026-09-28 — Chart plan generation (M1.2)
- **Seeding:** each patient uses `random.Random(sha256(patient_id))`. Regeneration is byte-identical, and a determinism test will enforce it in M1.7.
- **Concept IDs:** `bmi`, `age`, `comorbidity`, `weight_management_program`, `program_duration`, `diet`, `exercise`, `inadequate_response`, `concurrent_aom`. `concurrent_aom` (concurrent anti-obesity medication) replaces the planned `concurrent_glp1` so it also covers orlistat. The `drug_class` fact distinguishes GLP-1 RAs.
- **Stance semantics:** stance is relative to "this concept is satisfied."
  - For `program_duration`, start and continuation anchors are SUPPORTS, stop and lapse notes are CONTRADICTS, and undated or vague mentions are AMBIGUOUS. Each annotation carries `event_date` facts, so Phase 2 derives duration truth by code from dates plus the policy threshold, not from stance.
  - Numeric/structured concepts (`bmi`, `age`) are annotated NEUTRAL with value facts. Pass/fail against a threshold is policy-specific and computed in Phase 2.
  - Missing evidence produces **no** annotation. It is never CONTRADICTS (missing ≠ negative).
  - Counseling-only and single-component (diet-only or exercise-only) efforts are NEUTRAL for `weight_management_program`.
- **Hard negatives:** distractor notes that use weight, diet, exercise, or program vocabulary irrelevantly carry `relevance: false, hard_negative: true` annotations, so retrieval precision can be measured against them. The share of distractors that are traps rises with difficulty: about 14% easy, 23% missing-evidence, 33% ambiguous, 42% hard.
- **Requested drug:** every patient has `MedicationRequest/<id>-WEGOVY-REQ` (status `draft`, authored on the final PCP visit date), which represents the order under review. Concurrent-medication logic must exclude it.
- **Medications** are text-only CodeableConcepts, with no RxNorm codes, to avoid fabricating identifiers. GLP1-045 adds a `MedicationDispense` (recent Zepbound fill).
- **GLP1-023 (`med_list_absent`):** has no medication resources other than the Wegovy request. This is a deliberate exception to the 3–10 medication range.
- **Weights:** trajectories are anchored so the latest structured weight equals the spec's current weight. Historical BMIs stay on the same side of the 27 and 30 thresholds as the final BMI, except for the designed conflict in GLP1-041. Profiles are: inadequate (1–3.5% loss), limited (~4.5% loss, GLP1-035), flat, or gain.
- **Vitals:** every PCP visit and annual physical records weight, BMI, and BP Observations, capped at 6 dates. Any date a note cites a weight for also gets an Observation.
- **Comorbidity mentions** appear in the final PCP note, and in about half of the other PCP notes, as narrative evidence alongside the structured Condition. GLP1-022 and GLP1-034 have narrative-only comorbidities (no Condition resource). GLP1-028 has elevated BP with no hypertension diagnosis (AMBIGUOUS). GLP1-046 has a resolved hypertension Condition plus a narrative note that it's resolved (CONTRADICTS).
- Filler conditions exclude weight-related comorbidities such as OSA, T2D, OA, and CVD, so they can't accidentally satisfy a comorbidity criterion.

## 2026-09-28 — Note authoring (M1.3)
- **Frozen plans:** the chart plans in `data/_generation/plans/` are frozen as of the first note batch. Notes quote plan values (dates, weights, BMI, BP, labs), so any generator change that shifts the random sequence would invalidate them. The M1.7 determinism test pins plan hashes. Generator edits after this point must reproduce identical plans.
- **One post-M1.2 generator fix, made before any notes existed:** a lipid panel quoted in a lab-review note is now dated on that note's date, not the first vitals visit. Only Observation dates and IDs changed, in 9 patients.
- **Source format:** notes are authored as `data/notes/src/GLP1-xxx.txt` (blocks headed `=== <doc_id>`) and compiled by `scripts/compile_notes.py` into `data/notes/GLP1-xxx.json` (`{patient_id, notes: {doc_id: text}}`). Both formats contain only model-visible text.
- **Distractor details:** distractor notes adapt their specifics to the patient's actual chart. For example, an "allergy refill" becomes a triamcinolone refill for a patient with no allergy medication, or OTC advice where no prescription exists, so distractors don't introduce medications that are missing from the structured list.
- **Style:** clinician shorthand with headers, S/O/A/P sections, vitals, and plans. Program notes describe what the patient did, never whether a requirement was met. Final PCP notes include standard GLP-1 safety screening (MTC/MEN2, pancreatitis), which appears for every patient, so it isn't a signal.

## 2026-09-29 — Notes complete (M1.3/M1.4)
- **Evidence map pipeline:** `generate_plans.py` now writes plan-level annotations to `data/_generation/plan_annotations.json`, and the chart plans themselves are unchanged (verified byte-identical). `scripts/build_evidence_map.py` merges these with an **incidental comorbidity scan** of the authored notes to produce `ground_truth/evidence_map.json`.
  - The scan exists because distractor notes naturally mention comorbidities, e.g. "HTN on losartan" in a dental clearance, or a pharmacist caution about BP.
  - It only covers conditions the patient actually has. It is negation-aware, so "no hypertensive retinopathy" doesn't count. Each hit is tagged `source: incidental_scan`. 55 annotations were added, all hypertension, dyslipidemia, or prediabetes.
- **Distractor purity check:** a keyword scan of every distractor note for weight-management, lifestyle, diet-program, or GLP-1 language found **no** hits. Weight-program evidence exists only in notes that carry annotations.
- **Edits made during authoring to keep annotations aligned:**
  - Removed a "trying to lose weight for about a year" remark from GLP1-040's outside-clinic form, because it was unannotated duration evidence.
  - Removed hypertension references from two GLP1-046 distractors, since that patient's resolved-HTN signal lives only in annotated notes.
  - Distractor medication advice was kept to OTC products or to meds already on the structured list.

## 2026-09-29 — FHIR bundles and local data source (M1.5/M1.6)
- **No HAPI server (user decision):** the benchmark reads the cohort from the local FHIR R4 transaction bundles in `data/fhir/bundles/`, through `engine/pa_bench/fhir/client.py::LocalBundleClient`, a minimal read-only FHIR server supporting `read`, `search(type, patient)`, and `$everything`.
  - `scripts/verify_local_fhir.py` replaces the planned HAPI seed/verify scripts.
  - The bundles are still valid `PUT` transaction bundles, so they could be posted to any R4 server later without changes. A remote client would implement the same `FhirClient` protocol.
- **Validation:** `scripts/validate_fhir.py` validates every resource against **strict FHIR R4 4.0.1**, using fhir.resources 5.1.1 in an isolated `.venv-r4`, because that release needs pydantic v1. It also validates against R4B 4.3.0 in the main venv. Beyond schema, it checks:
  - reference integrity within each bundle
  - the ID format
  - that `meta.tag` holds exactly the neutral cohort tag
  - that the base64 note text round-trips to `data/notes`
  - Both runs pass with 0 errors, and a negative test confirmed invalid resources are rejected.
- **Resource modeling:**
  - DocumentReference text is inline base64 `text/plain`.
  - `DocumentReference.date` is an `instant` with a deterministic clinic-hours time derived from the doc ID.
  - `description` holds only the note type and author role, never hidden plan fields.
  - Observations use LOINC codes with UCUM units; BP is a panel with systolic and diastolic components.
  - Conditions use SNOMED codes. Medications are text-only.
  - `fullUrl`s are deterministic `urn:uuid` values (uuid5).
- **Determinism:** `build_fhir.py` output is byte-identical across runs.

## 2026-09-29 — Phase 1 closeout (M1.7)
- `engine/pa_bench/calc.py`: deterministic arithmetic for BMI, age, days, whole months, and % change.
  - Duration thresholds use **calendar whole months** (`whole_months_between`), so 2026-02-18 → 2026-08-18 counts as exactly 6 months, which is the GLP1-029 boundary.
  - Fractional months are used only for reporting.
- `engine/pa_bench/guard.py`: `assert_model_safe()` rejects payloads containing:
  - cohort-spec field names
  - class labels
  - distinctive challenge tags or states taken from the spec
  - annotation-only fields
  - evaluation IDs
  - hidden directory paths

  Answer-space words (PASS/FAIL, SUPPORTS/CONTRADICTS) are allowed in prompts. Every model call from Phase 4 on must pass through the guard.
- `tests/test_isolation.py` also statically checks that the model-facing packages (`fhir`, `retrieval`, `models`, `pipelines`) never reference hidden paths or ground-truth file names.
- Phase 1 was reviewed and accepted by the user on 2026-09-29.

## 2026-09-29 — Payer policies (P2.1/P2.2), pending user verification
- **Sources:** primary payer documents only, researched by three parallel agents and saved verbatim with URL, retrieval date, printed version and date, and a SHA-256 where it was a PDF.
  - BCBS FEP 5.99.030, effective 2026-07-01. Its criteria are identical to the 2026-02-13 version.
  - Aetna 4774-C P08-2025 v5, with an unlabeled page date of 2026-08-20.
  - UHC 2026 P 1114-22, effective 2026-09-01.
- Third-party summaries were **not** used. Several of them claim requirements, such as UHC "6 months documented lifestyle" or "BMI within 30 days", that are absent from the current primary documents.
- **Policy IDs** encode the version in force on the cohort index date.
- **`inadequate_response` is not scored:** no modeled policy requires it.
- The criterion status vocabulary (PASS / FAIL / INSUFFICIENT / CONFLICT), the PA aggregation rule, and the interpretation choices are proposed in `reports/policy_verification.md`. They are not final until the user signs off.

## 2026-09-29 — Policies VERIFIED by user (P2.3)
- **Documents and versions** approved as-is: `BCBS_FEP_WEGOVY_2026_07_01`, `AETNA_WEGOVY_4774C_2026_08_20`, `UHC_WEGOVY_P1114_22_2026_09_01`.
- **Adjunct criteria** (UHC `lifestyle_adjunct`, Aetna `adjunct_diet_and_activity`) **must be documented**:
  - No lifestyle documentation near the request → INSUFFICIENT.
  - Explicit non-adherence → FAIL.
  - Preview shown to the user: this rule changes the outcome for 4 patients (016, 017, 021, 036) and does not cause mass failure.
- **FEP program** read **literally**: any documented past or current participation counts, including an abandoned program (036, 037, 044). A declined program fails (043).
- **Medication conflicts** (FEP): newer explicit evidence wins.
  - 038 and 039 → PASS.
  - 045 (fill after "stopped") → CONFLICT.
  - Unknown current status (024, 050) and a med list that was never obtained (023) → INSUFFICIENT.
- **BMI:** the latest recorded structured BMI governs, so 040 at 29.7 with no comorbidity → FAIL. Elevated BP without a hypertension diagnosis (028) → CONFLICT.
- **Aetna 6-month program:** calendar whole months over a **continuous** period. Stop or lapse breaks continuity; vague or undated durations → INSUFFICIENT; contradictory start dates → CONFLICT. This was part of the verification packet and not objected to.

## 2026-09-29 — Ground truth (P2.4/P2.5)
- **Evaluator:** `engine/pa_bench/policies/evaluator.py` covers the code criteria (age, indication, BMI with comorbidity gating) and PA aggregation. The PA state is derived from the policy's `decision_logic` tree, so an `any_of` branch can rescue a failed sibling. The same module will be used by both pipelines.
- **Truth derivation:** `scripts/build_ground_truth.py` takes, per patient × policy:
  - age and BMI computed by code from the frozen plans
  - comorbidity from the spec (`truth_rules.comorbidity_truth`)
  - semantic and medication criteria from `engine/pa_bench/generation/truth_rules.py`, a reviewable per-state table with a rationale per entry, applying the user-approved interpretations
  - Aetna program duration computed from the dated program events in the plan, in calendar whole months

  Every criterion label stores its rationale and the IDs of the supporting, contradicting and ambiguous evidence.
- **Label design choices**, made for consistency with the approved rules:
  - Partial efforts (diet-only, exercise-only, counseling-only) are INSUFFICIENT for the program criteria rather than FAIL. The chart documents an effort, but not the required program.
  - GLP1-033 (Aetna): a program interrupted by a lapse, with about 7 months total but about 5 continuous → CONFLICT.
  - GLP1-042 and GLP1-049 (Aetna): contradictory program start dates → CONFLICT.
  - GLP1-050 (UHC/Aetna adjunct): very vague lifestyle statements → CONFLICT.
- **Distribution:** 86 READY / 56 NOT_READY / 8 REVIEW_REQUIRED across the 150 evaluations.
  - AETNA 24/22/4, BCBS 29/19/2, UHC 33/15/2.
  - All easy positives are READY and all easy negatives NOT_READY; tests enforce both.
- **Independent check:** the age and BMI labels are re-derived from the FHIR bundles in tests.

## 2026-09-29 — Evidence pipeline (Phase 3)
- **Structured features** come from `fhir/feature_extractor.py`, by code only. They include:
  - age on the request date
  - BMI, weight, and BP histories and latest values
  - latest labs
  - all Conditions, with weight-related ones flagged by a clinical keyword lexicon
  - all medications, with anti-obesity drugs flagged

  Everything is filtered to data on or before the request date. The **requested order** (a draft Wegovy MedicationRequest) is detected by code and excluded from the medication list.
- **Chunking:** paragraphs of at most 120 words, with short fragments merged forward. Each chunk keeps `resource_id`, `date`, `note_type`, and `chunk_id`.
- **Retrieval:** per-patient **BM25** (k1 = 1.5, b = 0.75) using criterion queries built from a general clinical lexicon (`retrieval/lexicon.py`) plus each policy's `retrieval.concepts`.
  - Top-K = 5 chunks with a relative score floor of 0.2.
  - Temporal criteria also get the **earliest and latest** relevant chunks.
  - Why BM25 and not embeddings: it's deterministic, transparent, and needs no API; the retrieval layer is swappable.
- **Comorbidity:** narrative comorbidity evidence is retrieved as a pseudo-criterion, `comorbidity`. It is consulted only for BMI 27–30.
- **Evidence profile:** `retrieval/profile.py` combines the request context, structured features, and per-criterion evidence into one profile. It is the **only** patient content any model receives, and it must pass `assert_model_safe`.
  - Profiles are cached under `data/cache/profiles/<config_hash>/`, so **every arm sees identical evidence**.
- **Raw-chart baseline for context reduction:** compact structured-resource JSON plus decoded note text, a median of about 9.0K tokens. The QA report's larger raw-bundle size (about 22.5K) is inflated by base64 and FHIR boilerplate and is not used as the baseline, to avoid overstating reduction.
- **Retrieval defaults were fixed a priori.** A K sweep of 3, 5, 8, and 12 is reported only.
  - Results: recall 0.93–0.96 and precision about 0.83 for program and adjunct criteria.
  - CONTRADICTS and AMBIGUOUS evidence recall are both 1.0, with 0 critical misses.
  - K = 3 would have cut CONTRADICTS recall to 0.65.

## 2026-09-29 — GPT baseline (Phase 4)
- **Model:** `gpt-6-sol`, set by the user via `OPENAI_MODEL`, through the OpenAI Responses API with **strict JSON-schema** structured output. Reasoning effort is `medium`, the model default, configurable via `OPENAI_REASONING_EFFORT`. No temperature is set.
- **Pricing** is in `config/model_pricing.json`, version `PRICING_2026_09_29`, read from OpenAI's primary pricing and model pages: $2.00 input / $0.20 cached input / $10.00 output per 1M tokens, with a long-context band above 272K.
  - A web-search summary had misstated output as $0.20. That figure was not used.
  - Cost is computed from raw usage at report time; reasoning tokens are billed as output.
- **Baseline design** (not crippled): **one call per PA case**. GPT receives:
  - the normalized policy, including verbatim payer text, parameters, and interpretation rules. The "USER-APPROVED" tags are stripped, and patient IDs are asserted absent.
  - the same cached evidence profile as the hybrid: request, structured data, and deduplicated chronological note excerpts, each tagged with the criteria it was retrieved for.

  GPT returns a status, confidence, evidence IDs, and a rationale per criterion, plus a PA state and a summary.
- **Scored PA state** is derived from GPT's criterion statuses with the **shared deterministic aggregator**, the same one the hybrid uses, so the arms differ only in how criteria are decided. GPT's self-reported `pa_state` is kept for a consistency metric.
  - Any criterion GPT omits → INSUFFICIENT, and flagged.
  - Evidence IDs not present in the profile are dropped, and noted.
- **Guard:** whole-identifier matching. The first live attempt was blocked before any API call because the policy parameter `min_duration_months` contains the spec field `duration_months`. The guard now matches whole identifiers only; the leak tests still pass, and a test asserts that all 150 GPT prompts pass the guard.
- **Provenance fix after the smoke test:** demographics now carry `Patient/<id>`. GPT had cited a non-existent `Patient.birthDate`. This is a formatting fix, not tuning.
- **Smoke test** (5 patients × 3 policies = 15 calls, `results/smoke/gpt_20260929T075313Z-3f7d08/`): 15/15 PA states and 75/75 criteria correct. Cost $0.232 total; 3.2–5.1K input and 460–950 output tokens per call; latency 7–16 s. **This is a smoke test, not a result:** these patients were chosen for coverage, not sampled.

## 2026-09-29 — Jev provider (Phase 5)
- **API contract** comes from the live docs (docs.typesafe.ai: `api.md`, `models.md`, primitives, confidence, and Jev 1.13 jaggedness), read on 2026-09-29.
  - Request: `POST https://api.typesafe.ai/v1/systemone` with a Bearer key and body `{state, model, questions}`.
  - Answers: Noul → `noul`; Choice → `choice`, `probabilities`, `confidence`; Score → `score`, `legend`, `probabilities`, `confidence`.
  - Usage returns input and output tokens.
- **Client:** a raw **httpx** client in `models/jev_provider.py`, not the SDK. This keeps the raw response JSON, including every probability, byte-for-byte, and keeps retries (429/529/5xx with backoff, honoring `retry-after`) under our own timing and logging.
  - The ground-truth guard runs on every request body before any network call.
- **Model:** pinned to **`jev-1.13.0`**, which is where `jev-latest` pointed on 2026-09-29. It's used because `JEV_MODEL` and `JEV_BASE_URL` are blank in `.env`.
  - The response's versioned `model` is logged with every call.
- **Pricing:** $0.042 per 1M input tokens, output free. Added to `config/model_pricing.json` with its source.
- **Design implications from the Jev 1.13 jaggedness page**, which Phase 6 will follow:
  - Keep all date and duration arithmetic in code; Jev classifies events and extracts parts through a Choice with an explicit "none" option.
  - Filter the state to the retrieved evidence only.
  - Write literal, aligned instructions and criteria.
  - Ask each decision once, and enforce structural rules in code.
- **Guard interaction:** Choice **option names are sent to the model**, so they must not coincide with hidden cohort vocabulary.
  - An option named `status_unknown` collided with a hidden spec scenario name, and the guard blocked the call. It was renamed `unclear_if_still_taking`.
  - Phase 6 tests will assert that every hybrid question set passes the guard.
- **Smoke test** (`results/smoke/jev_20260929T080242Z-3b3c2b/`): 5 calls with 1–6 questions each, 100–220 ms per call, $0.0004 in total. Raw probabilities were preserved exactly.
  - Judgments were sensible: negation → declined (confidence 0.98–1.0); start → stop → restart → ongoing traced; stopped Ozempic and Zepbound detected; elevated BP without diagnosis → "suspected".
  - A few low-confidence chunks (0.47–0.74) appeared — the router's escalation targets.

## 2026-09-29 — Hybrid narrative and escalation policy (user-directed)
- **Escalation** (user choice): only criteria below the Jev confidence threshold escalate, in **one GPT call per case** covering just those criteria, with the same shared evidence. Confident criteria keep Jev's answer.
- **Narrative** (recommended to the user, who asked for advice):
  - The hybrid generates a GPT submission narrative **only for READY cases**. NOT_READY and REVIEW cases get an exact code-built summary of the missing requirements and review reasons.
  - The GPT baseline keeps its in-call summary (about 100 output tokens, no extra call).
  - Hybrid cost and latency are reported both **decision-only** and **end-to-end**, with the narrative as its own line item.
  - Configurable via `HYBRID_NARRATIVE=ready_only|all|none`.

## 2026-09-29 — Adjunct recency window
- "Documented near the request" for UHC `lifestyle_adjunct` and Aetna `adjunct_diet_and_activity` is operationalized as **within 180 days before the request date** (`params.recency_window_days`).
- It lives in the policy params and interpretation notes, so **both pipelines see the same rule**.
- It is consistent with every approved ground-truth label: 017 at about 9.5 months and 021 at about 8.5 months → INSUFFICIENT; 032 at about 2.5 months → PASS. Ground truth was rebuilt and is unchanged.

## 2026-09-29 — Hybrid pipeline (Phase 6)
- **Architecture** (`pipelines/hybrid.py`):
  - **Code** decides age and indication, the BMI arithmetic, and the use of structured comorbidity Conditions.
  - **One Jev fan-out request** per case (8–49 questions, median 25, about 1.4–7.9K tokens) reads each retrieved note chunk:
    - event type (8 options)
    - diet, activity, and formal-program Nouls
    - stated start month/year and a duration bucket (only for policies with a duration rule)
    - medication status (6 options; FEP only)
    - one comorbidity Choice, asked only when 27 ≤ BMI < 30 and no active structured comorbidity exists
  - **Code composition** (`hybrid_rules.py`) handles every date, window, duration, recency comparison, conflict, and medication reconciliation, applying the same approved rules as the ground truth. The rule design follows the Jev 1.13 jaggedness guidance.
  - **Router:** Jev-decided criteria with confidence below the threshold go to **one** GPT call covering only those criteria, with the same shared evidence and the same prompt as the baseline, restricted to the escalated IDs.
  - **Aggregation:** the shared deterministic aggregator produces the PA state.
  - **Narrative:** a GPT narrative only for READY cases (`HYBRID_NARRATIVE`).
- **Criterion confidence:** flip Jev answers cumulatively from least to most confident; confidence is the highest confidence among the answers that would all have to be wrong for the status to change. This catches both a single decisive weak answer and several redundant weak ones, and ignores uncertainty on unused branches.
  - Code-only criteria have confidence 1.0.
  - The Noul confidence is |2p − 1|, the same scale as a binary Choice.
- **Development transparency:** the hybrid questions and rules were revised once after smoke-testing 5 cohort patients. There is no separate development set; this is a stated limitation.
  - **(a)** The event options now state that starting or planning a weight-loss medication is not a lifestyle program. Jev had read "start Wegovy" as `program_started` for GLP1-016.
  - **(b)** The UHC adjunct rule now requires a lifestyle signal (diet, activity, or formal program).
  - **(c)** Confidence moved from single-flip to cumulative-flip sensitivity, found by synthetic unit tests, not cohort results.
  - All three are generic fixes, not case patches. The GPT baseline received only a provenance formatting fix (`Patient/<id>` on demographics).
- **Synthetic-answer unit tests** (`tests/test_hybrid_rules.py`) exercise every rule path without cohort data, and orchestrator tests use a fake Jev and a fake GPT.
- **Smoke test** (same 5 patients × 3 policies as the GPT smoke test): 15/15 PA and 75/75 criteria correct.
  - Cost $0.049 for the hybrid vs $0.232 for GPT.
  - Decision latency 0.16–0.42 s (a 6.2 s case included one escalation) vs 7–16 s for GPT.
  - GPT calls: 10 narratives (READY cases) plus 1 escalation.

## 2026-09-29 — Benchmark execution (Phase 7)
- **Runner:** `scripts/benchmark.py`. Each run directory holds `run_manifest.json` (written first), `results.jsonl` (the checkpoint; resume skips completed evaluations), and `traces.jsonl` (one row per model call).
- **Call caching:** model calls are cached on disk, keyed by the exact request (model, settings, prompt or state, schema).
  - Cached records keep their original usage, latency, and request ID, flagged `cache_hit`.
  - `--force` bypasses the cache; failures are never cached.
  - Threshold sweeps reuse the Jev reads and any identical GPT escalation or narrative calls.
- **Execution:** concurrency 4 for both arms. The arms ran sequentially, not overlapping, so latency is comparable.
  - The repo has no git commits, so manifests carry `git_commit: null` plus a `source_tree_sha256` over code, policies, config, data, and ground truth.
- **Runs** (all 150/150, 0 errors):
  - `main_gpt`: GPT-only baseline.
  - `main_hybrid_t0.90`: the **pre-registered headline** threshold.
  - `sweep_t0.60 … sweep_t0.95`: sensitivity analysis only.
- **Headline threshold** stays **0.90**, per the spec's rule against optimizing thresholds on the test cohort. In the sweep, 0.80 scored highest on PA accuracy; this is reported, **not** adopted.
- **Actual new API spend** across all runs: $4.25 total — OpenAI $4.22, Jev $0.038. This covers the GPT baseline ($2.33), the hybrid headline run, and the new escalation calls in the sweep.

## 2026-09-29 — Evaluation (Phase 8)
- **Pipeline:** `scripts/evaluate.py` produces `results/` and `presentation_results/`. `scripts/write_reports.py` generates `reports/evaluation_report.md` and `reports/failure_analysis.md` directly from those files, so no numbers are copied by hand.
- **Statistics:** 95% CIs use a **patient-cluster bootstrap** (2,000 reps, fixed seed), because the three policy evaluations of one patient are correlated. The paired PA-state comparison uses an exact McNemar test.
  - The criterion-level McNemar test is reported as descriptive only, since criteria within a case are correlated.
- **Cost reporting:** costs are reported **end-to-end** and **decision-only**, the latter excluding the hybrid's READY-case narratives. Per-criterion cost and token attribution:
  - GPT arm: the single call is split equally across the case's criteria.
  - Hybrid: code criteria cost 0; the Jev call is split across the Jev-evaluated criteria; an escalation call is split across the escalated criteria.
  - Attribution reconciles exactly with case totals.
- **Context-reduction measures:** "all model input", i.e. GPT decision input plus Jev input, and "frontier-only", i.e. GPT decision input. Jev's input includes question text, so the hybrid's all-input reduction is lower than its frontier reduction.
- **Calibration:** Jev is scored at criterion level using its **pre-routing** confidence against the correctness of its own status. GPT's self-reported confidence is scored on the same criterion set for comparison. Bins report n.
- **Failure categorizer priority:** retrieval → missing-vs-negative → criterion + challenge-tag family → policy logic → semantic. MODEL_OVERCONFIDENCE (wrong at confidence ≥ 0.90) is a secondary flag.
  - The missing-vs-negative check was moved ahead of tag mapping after the first evaluation pass. The dominant GPT error, BMI 27–30 with no comorbidity labeled INSUFFICIENT instead of FAIL, was being scattered across tag categories.
  - This is an evaluation-logic change only; no pipeline or prediction changed.
- **Interesting cases:** selected by objective criteria: disagreements between arms, a Jev high-confidence error, an escalation that fixed an answer, an escalation that changed a correct Jev answer (PA-impacting cases preferred), a medication contradiction, a temporal case, the largest token saving, and the maximum hybrid latency. No characterization of which arm is better.
